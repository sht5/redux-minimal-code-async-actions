One Redux middleware replaces the code written around every async call — action types, dispatch calls, and reducer wiring.

Problem

Entry 02

The boilerplate tax

Every async call in Redux traditionally needs three action types, three creators, and the code to dispatch them by hand.

  • IN PROGRESS

    Action type + creator, fired before the call

  • SUCCESS

    Action type + creator + reducer case, fired on resolve

  • ERROR

    Action type + creator + reducer case, fired on reject

N async calls × 3 states = 3N pieces of repeated code.

Approach

Entry 03

One middleware, one flag

Add async: true to any action. The middleware takes it from there — no sagas, no thunks.

const getUser = {
    type: 'GET_USER',
    async: true,
    httpMethodToInvoke: api.fetchUser,
    params: [userId]
};
Mechanism

Entry 04

What the middleware does

  • 01

    Detects async: true on the action

  • 02

    Dispatches TYPE_IN_PROGRESS

  • 03

    Calls httpMethodToInvoke(...params)

  • 04

    Dispatches _SUCCESS or _ERROR

Source

Entry 05

The middleware, in full

redux_async_middleware.js

const asyncActionsMiddleware = store => next => action => {
    if (!action.hasOwnProperty('async')) return next(action);

    const { httpMethodToInvoke, params, type } = action;
    const inProgressType = `${type}_IN_PROGRESS`;

    store.dispatch({ type: inProgressType });

    httpMethodToInvoke(...params)
        .then(result => store.dispatch({
            type: `${type}_SUCCESS`, ...result
        }))
        .catch(err => store.dispatch({
            type: `${type}_ERROR`, err
        }));

    return next(action);
};

Summary

Entry 07

Why it's worth it

i.

Drop-in middleware — no sagas or thunks to learn.

ii.

Every async call collapses to a single action object.

iii.

The resolved payload spreads straight into the SUCCESS action.
